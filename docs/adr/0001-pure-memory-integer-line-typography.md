# ADR 0001: 纯内存整数行排版引擎与字符级进度锚点

- **状态**: Accepted
- **决策日期**: 2026-09-16
- **参与者**: 藏书阁核心架构组

## 背景与问题

传统阅读器使用原生 WebView 或普通 ListView 渲染正文时，普遍存在以下致命缺陷：
1. **切半行问题**：视口底部字符常被下边界横切一半，阅读观感极差；
2. **转屏与改字号跳页**：以“页码”为持久化进度时，一旦用户调整字号、行间距或旋转屏幕，总页数发生剧变，读者视线焦点彻底丢失；
3. **大章卡顿与内存泄漏**：网文单章往往超万字，DOM 或大型 Widget 树会导致内存占用激增与翻页掉帧。

## 决策

我们决定设计并实现纯内存自研排版引擎（`TypographyEngine`），遵循以下技术决策：

1. **整数行绝对截断数学公式**：
   单页最大排版行数 $N$ 严格遵循截断算式：
   $$N = \lfloor (H_{avail} + S_{line}) / (H_{line} + S_{line}) \rfloor$$
   仅当剩余可用高度能够容纳完整一行字符的包围盒（Bounding Box）时才允许绘制，视口底部绝不绘制残损半行。
2. **字符级进度锚点 (`CharAnchor`)**：
   进度持久化不再存储虚拟页码，仅存储章内字符偏移索引 `charOffset`。
   用户在修改字号、行距或转屏后，引擎重新计算所有页面，并基于 `charOffset` 执行逆向二分查找定位新页面，确保读者视线聚焦的首个字符分毫不动。
3. **CJK 出版级标点避头避尾禁则**：
   内置 35 类标点禁则，禁止行首出现逗号、句号、引号后半部等闭合标点，禁止行尾出现前置引号或书名号前半部。

## 后果与影响

- **正面收益**：翻页体验达到出版级标准，完全根除切半行现象，改字号/转屏定位零脱节；
- **负面成本**：跨端自适应计算需在字体度量完成后进行，字号变动需毫秒级触发单章轻量重新分页（已通过纯内存 LRU 分页缓存抵消开销）。
