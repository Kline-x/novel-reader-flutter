## 〇-补、分包 versionCode 偏移（发版链路致命项，已修并复验）

真机装包被系统拒绝才暴露：

```
INSTALL_FAILED_VERSION_DOWNGRADE: Update version code 4003 is older than current 6003
```

`--split-per-abi` 会把每个包的 versionCode 重写为 `abiCode * 1000 + base`。**实测**：

| ABI | 实测 versionCode | 偏移 |
| :--- | ---: | ---: |
| armeabi-v7a | 5003 | +1000 |
| arm64-v8a | 6003 | +2000 |
| x86_64 | **8003** | **+4000**（abiCode 是 4，不是 3——3 留给了 x86） |

而 `version_manifest.json` 写的是 pubspec 的基础号 4003，客户端拿自己的真实 6003 去比，
`4003 > 6003` 恒为假 → **所有用户永远收到「已是最新」，新版本再也推不出去**。
与用户最初反馈的更新问题同根，只是换了形态。**偏移不能靠猜**。

**修复**：
1. `tool/sync_version_manifest.dart` 改为用 **aapt2 从 APK 读真实 versionCode**
   （自动定位 `ANDROID_HOME/build-tools`），读不到才按公式推算并告警；
2. CI 门禁改为按 base 取模校验，识别分包号；
3. 客户端 `AppVersionInfo.effectiveVersionCodeFor(abis)`，按本机 ABI 取号比较。

**真机复验**：机上 arm64 包 6003、清单 arm64 变体 6003 →
设置页点「检查更新」正确提示「当前已是最新版本 (v1.0.2)」，不再误报。
（该次截图含用户微信通知横幅，已删除未归档。）

### <a id="d-01"></a>D-01 · P0 · 换源后串书

**复现**：打开《十日终焉》（笔趣阁ZWX，1000 章，读到第 4 章「灾难?」）→ 顶栏「换源」→ 选「笔趣阁CP」。

**实际结果**：

| | 换源前 | 换源后 |
| :--- | :--- | :--- |
| 目录章节数 | 1000 | **188** |
| 第 2 章 | 说谎 | 遇事不决，可问春风 |
| 第 3 章 | 有技术的人 | 道法三千六百门，人人各执一苗根！ |
| 第 4 章 | 灾难? | 诡考 |
| 第 9 章 | 难以接受的真相 | **泥瓶巷陈平安** |
| 第 8 章 | 摊牌 | **张小凡** |
| 第 12 章 | 你们的家乡 | **无敌齐夏** |

换源后拿到的是一本把《剑来》陈平安、《诛仙》张小凡、《十日终焉》齐夏混在一起的**同人文**，
正文内容是"金词条""古卷""老学究"，与《十日终焉》的密室生死游戏题材毫无关系。

**而顶栏依然显示《十日终焉》，进度依然是"第 4 章"** —— 用户完全不会意识到自己已经在读另一本书。

**根因**（`reader_screen.dart` 换源逻辑）：

```dart
final matches = searchRes.where((b) {
  final t = b.title.replaceAll(RegExp(r'[《》【】\s]'), '');
  return t == cleanName || t.contains(cleanName) || cleanName.contains(t);  // ← 双向包含
}).toList();
if (matches.isNotEmpty) {
  final match = matches.first;   // ← 直接取搜索结果里的第一个
```

`t.contains(cleanName)` 让任何**书名里含有"十日终焉"字样**的作品都算命中，
再加上 `matches.first` 不做优选，于是随手抓到一本同人文就换过去了。

这与代码审查里记过的 `StorageService.isBookInShelf` 双向 `contains` 是同一类缺陷，
但后果严重得多——那个只是误判"已在书架"，这个会直接把用户正在读的书换成另一本。

**修复方向**：
1. 匹配优先级：书名精确相等 > 书名相等且作者相等 > 其余一律不自动采用；
2. 无精确匹配时，弹出候选列表让用户自己选，并显示各候选的书名/作者/章节数；
3. 换源后校验新目录的章节数与原目录的偏差，偏差过大（如不足原来的 1/3）时二次确认；
4. 顶栏/详情页展示当前生效的书源与目录章节数，让串书可被用户察觉。

### <a id="d-02"></a>D-02 · P0 · 版本号三处不一致，新包无法安装

**现象**：把本次构建的包装到机上时被系统拒绝：

```
INSTALL_FAILED_VERSION_DOWNGRADE: Update version code 2002 is older than current 4002
```

**实测三处版本号**：

| 来源 | 值 |
| :--- | :--- |
| 机上已安装 APK（`dumpsys package`） | `versionCode=4002`, `versionName=1.0.1` |
| 仓库 `pubspec.yaml` | `1.0.1+2002` |
| 仓库 `version_manifest.json` | `versionCode: 2` |

**这正是「已经是最新版本了，检查版本更新还是能更新，更新之后提示当前版本比下载的版本高」的根因**——
客户端自报版本、线上清单版本、真实安装包版本三者各说各话。

**本次处置**：已把 `pubspec.yaml` 与 `version_manifest.json` 统一到 `1.0.2 + 4003`，安装成功且用户数据完整保留。

**仍需做的**：
1. `version_manifest.json` 的 `versionCode` 由构建流程从 `pubspec.yaml` 自动写入，禁止手工维护；
2. CI 门禁：`pubspec.yaml` 的 build number 必须 > 上一个 release tag 的 build number；
3. 发布时把真实 `sha256` / `fileSize` 写进清单——否则本次新增的安装包完整性校验会把自家的包拦下。

### <a id="d-03"></a>D-03 · P1 · 跟随系统深色模式完全失效

**复现**：设置页「跟随系统深色模式」保持**开启** → `adb shell cmd uimode night yes`（确认返回 `Night mode: yes`）
→ 应用界面仍是浅色 → **强杀应用重新冷启动** → 仍是浅色。

**结论**：不是"不支持热切换"，而是**彻底不生效**。

**根因**（`lib/core/theme/theme_provider.dart:15-28`）：

```dart
Future<void> _loadInitialTheme() async {
  final themeStr = await StorageService().getGlobalTheme();
  if (themeStr == 'system') {
    _isFollowingSystem = true;        // ← 只记了标志位
                                      // ← 完全没有根据系统亮度去设置 state
  } else { ... }
}
```

于是 `state` 始终保持构造函数里的默认值 `SoftPaletteType.parchment`（羊皮纸，浅色）。
只有用户**手动拨动开关**时走的 `setFollowSystem(true, currentBrightness: ...)` 才会按亮度设置主题。

另外全工程没有任何地方监听 `platformBrightness` 变化（无 `didChangePlatformBrightness`），
所以运行中系统切换深浅色，应用也毫无反应。

**修复方向**：
1. `_loadInitialTheme` 读到 `'system'` 时，用 `PlatformDispatcher.instance.platformBrightness` 决定初始 palette；
2. 在 `MainScaffold` 或根 Widget 注册 `WidgetsBindingObserver`，在 `didChangePlatformBrightness` 里刷新 palette；
3. 同时修掉设置页的显示矛盾：跟随系统开启时，四个主题 Chip 应置灰或标注「已跟随系统」，
   而不是像现在这样高亮着「极夜黑」却渲染浅色界面。

### <a id="d-04"></a>D-04 · P1 · 设置页最后一项被底栏遮挡

**现象**：设置页首屏最底部，「WiFi 局域网无线传书」的副标题
「电脑浏览器访问局域网 IP 直传 TXT/EPUB」与底栏的「书架」「发现」图标**直接重叠**，文字糊成一团。

**根因**：底栏是 `Stack` 上的 overlay，但设置页滚动列表没有预留等高的底部内边距。
新底栏总高 = 28（渐隐带）+ 58（内容）+ 底部安全区，比旧版更高，重叠因此更明显。

**注**：发现页与书架页的渐隐效果良好（内容自然淡出，无硬边），问题只出在设置页缺少底部 padding。

**修复方向**：设置页列表底部加 `SliverPadding(bottom: 底栏总高 + 16)`；
书架页此前写死的 `bottom: 110` 也需随新底栏高度重算。

### <a id="d-05"></a>D-05 · P1 · 滚动模式退出重进后位置未还原

**复现**：排版抽屉切到「无缝流式」→ 连续向下滚动若干屏 → 返回书架 → 重新打开同一本书。

**期望**：回到退出时的滚动位置。**实际**：停在章节**开头**。

**说明**：这是上一轮修复 ISSUE-15 时**没有做到位**的部分。进度上报（`_reportScrollProgress`）已生效，

**修复方向**：改为给 `ScrollController` 传 `initialScrollOffset`，
或在 `maxScrollExtent > 0` 之前重试若干帧后再跳转。

### <a id="d-07"></a>D-07 · P1 · 阅读器配色与应用主色冲突

**现象**：应用整体主色是绿色（书架、设置、底栏选中态、按钮），
但**阅读器内部**的控件全是蓝色 `#5B7FFF`：

- 底部进度滑块的滑块头与已选轨道
- 排版抽屉的字号滑块
- 翻页模式「覆盖」选中态的蓝色填充
- 主题色圆点的选中描边与对勾
- 目录抽屉顶部的「笔记 / 缓存 / 倒序」
- 目录里当前章节的高亮行

**感受**：从书架进到阅读器像换了一个 App。

**根因**：阅读器一系列组件硬编码了 `const Color(0xFF5B7FFF)`，没有走 `SoftTheme` 的 `colors.accent`。

**修复方向**：全局搜 `0xFF5B7FFF` 替换为主题 accent；
阅读器有独立的 `ReaderThemeOption`，需为其补一个与全局主色协调的 accent，而不是各处写死。

### <a id="d-08"></a>D-08 · P2 · 换源面板的延迟与状态是伪造的

**现象**：换源面板里 12 组书源的延迟依次是
**45ms / 58ms / 71ms / 84ms / 97ms / 110ms…** —— 完美的 +13ms 等差数列。

对照代码 `reader_screen.dart`：`final latency = 45 + (index * 13) % 120;` —— 按下标算出来的假数据。

同屏还有另外两处写死文案：
- 每条书源的副标题都是「目录已核准 · 最新更新至当前章」
- 右上角固定显示「已连通 12 组稳定书源」

**这与已修复的假电量、离线假 APK 属于同一类问题：把未实现的能力伪装成已实现。**
而 `MultiSourceService.pingAllSources()` / `NetworkClient.measureLatency()` 已经实现了真实测速，只是没接上。

**修复方向**：面板打开时并发真实测速，未返回前显示「测速中」，失败显示「不可达」并置灰；
「目录已核准」改为真实探活结果或直接移除。

### <a id="d-09"></a>D-09 · P2 · 换源静默丢弃离线缓存

**现象**：《十日终焉》换源前徽标是「4 章离线」，换源后变成「1 章离线」，全程无任何提示。

**说明**：这是上一轮修复 ISSUE-09（换源后清空旧源正文缓存）的**副作用**——清缓存本身是对的
（否则会串着显示旧源内容），但用户辛苦下载的离线章节就这么没了，且毫不知情。

**修复方向**：换源前弹确认框「切换书源将清除已下载的 N 章离线缓存，是否继续？」。

---

### <a id="d-10"></a>D-10 · P2 · 行距三个 Chip 全部未选中

**现象**：排版抽屉里「紧凑 / 舒适 / 宽松」三个 Chip 呈现的都是未选中样式，看不出当前用的是哪一档。

**推测根因**：选中判定用行距数值精确相等，而当前行距是由字号联动算出来的（`fontSize * 1.68`），落不到任何预设值上。

**修复方向**：选中判定改为「最接近的一档」，或把行距改成三档离散值。

---

### <a id="d-11"></a>D-11 · P2 · 阅读页底部留白偏大

**现象**：第 1/5 页正文在「嘴。」处结束后，到页脚还有约 4~5 行空白。整章 5 页每页都如此，观感上像"没排满"。

**推测根因**：`PagingConfig.padBottom`（安全区 + 28）叠加段间距余量估算偏保守，整数行截断时留下超出必要的富余。

**修复方向**：核算 `availHeight` 与实际渲染高度的差值，把保守余量压到 1 行以内。

---

### <a id="d-12"></a>D-12 · P2 · SnackBar 完全盖住底栏

**现象**：「当前已是最新版本」「已从书架移出《…》」等浮动 SnackBar 贴在屏幕最底部，把整条底栏完全盖住。

**修复方向**：给 SnackBar 设置 `margin` 抬高到底栏之上。

---

### <a id="d-13"></a>D-13 · P2 · 阅读器顶栏过于拥挤

**现象**：顶栏从左到右是 `返回 · 十日终焉 · 已入架 · 换源 · 笔记 · 书签 · 离线`，
书名与第一个胶囊之间几乎没有留白，5 个胶囊紧紧挨在一起，指尖很难精准点中。

**修复方向**：常用的留在顶栏（换源 / 书签），其余收进「更多」菜单。

---

### <a id="d-14"></a>D-14 · P2 · 本地书的长按菜单仍显示「离线下载全本」

**现象**：本地导入的 TXT 书长按后，菜单里依然有「离线下载全本」。本地书全部内容已在设备上，该项无意义。

**说明**：阅读器内部已经对本地书做了拦截（点"离线"会提示"当前为本地图书…无需重复下载"），
但书架长按菜单没有同步这个判断。

**修复方向**：`isLocal` 为真时不渲染该菜单项。

---

### <a id="d-15"></a>D-15 · P2 · multipart 文件名非 UTF-8 时产生乱码书名

**现象**：用 curl 以 multipart 形式上传、且 `Content-Disposition` 里的 filename 是 GBK 字节时，
书名落成 `��������.txt`。

**边界说明**：应用内置网页走的是 `?filename=` + `encodeURIComponent`（UTF-8 百分号编码）路径，
**实测中文书名完全正常**（`剑来测试.txt`）。所以这只影响非标准客户端，属健壮性问题而非主链路缺陷。

**修复方向**：`_extractMultipartFile` 解析 filename 时，
优先识别 RFC 5987 的 `filename*=UTF-8''...` 形式；解码出不可打印字符时回退为时间戳命名。
