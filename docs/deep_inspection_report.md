## 一、第 1 轮：排版、主题配色、电量可视性与边界视距实测

### 1.1 [严重缺陷] 电池图标无电量数字百分比且多主题下几近隐形 (直击用户关切)
- **真机实测证据**: 实测截图 `nr1_08_parchment_theme.png`、`nr1_09_parchment_fullscreen.png`、`nr1_10_green_fullscreen.png`
- **真机实测现象**: 在全套主题（纯白、羊皮纸、深灰墨绿、纯黑夜间）下，阅读器右下角的电池图标仅有一圈极细的单线边框，**内部完全没有任何数字百分比（例如 72%）**；更严重的是，在羊皮纸与墨绿护眼底色下，该图标的色彩对比度低至 **1.8:1**，在正常光线或弱光阅读下几乎如同隐形，读者根本无法获知手机剩余电量，产生极强用电焦虑。
- **成因代码定位**: `lib/features/reader/presentation/page_painter.dart` 第 162-189 行绘制电池组件使用单色外框，未接入电量百分比文字或电量条填充；颜色直接复用了淡色文字颜色。
- **优化方案**:
  1. 在电池图标左侧或内部增加精准电量百分比文字（如 `72%`）；
  2. 根据当前主题背景动态计算符合 WCAG 4.5:1 的高对比度高亮色彩，在电量低于 20% 时变为警戒琥珀黄/红色。

### 1.2 [体验瑕疵] 羊皮纸与墨绿护眼主题下，页眉章名与页脚页码颜色过浅
- **真机实测现象**: 顶部章节标题、当前时钟以及底部页码使用了与正文反差过大的弱化淡灰/灰土色，阅读过程中扫视页眉页脚非常吃力。
- **优化方案**: 重调 `SoftPaletteType.parchment` 与 `SoftPaletteType.green` 下的 `textSecondary` / `metaText` 灰阶，确保弱化信息既不抢正文风头又保持清晰可辨。

### 1.3 [视觉排版] 顶部第一行正文与挖孔屏边距过于逼仄，底部末行文字贴紧页码
- **真机实测现象**: 在真机 1440×3168 居中挖孔屏下，正文首行文字上边距与顶部状态栏/摄像头仅留约 8dp，压迫感强烈；正文最后一行文字直接与底部页码紧紧贴在一起。
- **成因代码定位**: `lib/features/reader/services/book_layout_engine.dart` 页面有效排版高度计算时，未给状态栏挖孔安全区和底栏留足舒适留白。
- **优化方案**: 将阅读器上下外边距从固定的数值升级为结合 `MediaQuery.of(context).padding.top` 与黄金比例留白动态计算，保证字里行间的呼吸感。

### 1.4 [重大体验缺陷·用户专项指出] 阅读页顶部粗暴全屏，与其他页面顶部断层割裂未对齐
- **真机实测现象**: 书架页、发现页、设置页均具备规范的 `SafeArea` 与顶部下沉，而阅读页一打开强制进入 `SystemUiMode.immersiveSticky` 隐藏状态栏全屏，进出时屏幕上下剧烈抽搐跳跃，正文紧贴挖孔摄像头，呼出菜单再次晃动。
- **成因代码定位**: `reader_screen.dart` 第 89 行粗暴隐藏系统栏，未与应用全局顶部基准标尺对齐。
- **优化方案**: 改用 `SystemUiMode.edgeToEdge` 透明沉浸状态栏，页眉基准线严格与书架/设置顶栏对齐，进出平滑稳定。

### 1.5 [重大视觉灾难·用户专项指出] 黑色主题下排版抽屉黑底黑字“字一个都看不见”
- **代码深度定位**: `lib/features/reader/presentation/typography_drawer.dart`：
  - 第 41 行：当 `currentTheme.isDark` 为 true 时，卡片背景设为了深黑色 `Color(0xFF1E2022)`；
  - 第 71 行、104 行、114 行、128 行：“字号”、“行距”、“翻页”等文字标题，以及字号数值文本，**全部未声明任何 `color` 属性**；
  - 第 223 行：`_buildRoundButton` 内的 `Icon(icon, size: 18)` 也**未指定任何 `color` 属性**；
  - 第 252 行：`_buildLineSpacingChip` 中未选中时的字体颜色直接返回了 `null`；
  - **严重后果**: 由于应用全局使用的是浅色 ThemeData，所有未声明颜色的文本和图标全部默认继承了全局的深黑色（`Colors.black` / `Color(0xFF1C1B1F)`）。在深黑色底色上直接绘制深黑色文字，**发生完全融为一体的“黑底黑字隐形灾难”，字一个都看不见！**
- **优化方案**:
  1. 在 `TypographyDrawer` 中根据 `isDark` 动态定义前景色：`final textColor = isDark ? Colors.white : const Color(0xFF1F2329);`、`final subTextColor = isDark ? Colors.white70 : const Color(0xFF646A73);`；
  2. 强制将抽屉内所有“字号/行距/翻页”标题、数字、未选标签、A-/A+ 图标显式绑定 `textColor` 与 `subTextColor`，确保深色下白字清晰锐利。

### 1.6 [重大体验缺陷·用户专项指出] 黑色主题下左侧目录抽屉未跟随变黑，依然维持亮色
- **代码深度定位**: `lib/features/reader/presentation/catalog_drawer.dart`：
  - 第 73 行：`color: Theme.of(context).scaffoldBackgroundColor,`
  - 第 88、96、163、168 行：全部依赖外层全局的 `Theme.of(context)`；
  - `reader_screen.dart` 在传递参数给 `CatalogDrawer` 时，根本没有传入当前的阅读主题或 `isDark` 属性！
  - **严重后果**: 用户在阅读器中无论怎么切换正文主题（如切换为深黑夜间模式），左边呼出的目录抽屉永远是全局默认的纯白天白色/浅灰底，夜间打开极其刺眼，视觉体验严重割裂脱节。
- **优化方案**:
  1. `CatalogDrawer` 增加 `final ReaderThemeOption theme` 或 `final bool isDark` 属性；
  2. `reader_screen.dart` 在构建 `CatalogDrawer` 时传入当前的 `_currentTheme`；
  3. `CatalogDrawer` 内部的背景色、搜索框、章节列表文字、分割线全部根据传入的主题自适应渲染为深色高质感水墨黑。

## 二、第 2 轮：听书 / TTS 语音朗读、悬浮控制与夜间体验实测

### 2.1 [严重缺陷] 启动 TTS 朗读时强制从章节首句从头播放
- **真机实测证据**: 实测截图 `nr2_01_tts_entry.png` ~ `nr2_03_tts_options_selected.png`
- **真机实测现象**: 当用户已经翻阅到某一章节的第 3 页或末尾时，呼出菜单点击「听书」，TTS 播放器完全无视当前读者阅读所处的段落位置，强制从当前章节的第 0 句重新读起。
- **成因代码定位**: `lib/features/reader/presentation/reader_screen.dart` 呼出 TTS 时，传递给 `TtsController.start(...)` 的起始句子索引硬编码为 `startIndex: 0`。
- **优化方案**: 根据当前视口正在展示的起始段落与字符偏移，精准映射为该章节当前可视段落的句子索引，做到“读到哪听到哪”。

### 2.2 [严重缺陷] TTS Mini 悬浮条在菜单展开态和沉浸阅读态均发生严重遮挡
- **真机实测证据**: 实测截图 `nr2_04_tts_mini_bar.png`、`nr2_05_tts_mini_in_reading.png`
- **真机实测现象**:
  1. 在展开阅读菜单时呼出 Mini 悬浮条，Mini 条直接重叠覆盖在底部章节翻页进度滑块的正上方，严重遮挡了翻页控制与底栏功能按钮；
  2. 在沉浸正文阅读时，Mini 条停留在屏幕最底部，死死遮住了正文底部的章节页码与电量图标。
- **成因代码定位**: `lib/features/reader/presentation/tts_mini_player.dart` 采用硬编码绝对定位 `Positioned(bottom: 24, left: 16, right: 16)`，未根据阅读菜单显隐状态和系统导航栏高度动态联动位移。
- **优化方案**: 引入悬浮拖拽吸附能力，或随菜单弹出向上平移避免遮挡关键翻页控制器；沉浸态自动避让页码与电量。

### 2.3 [视觉刺眼] 深色阅读模式下 TTS Mini Player 呈现高亮纯白胶囊
- **真机实测现象**: 当读者在夜间使用纯黑或深灰模式阅读时，呼出的 TTS Mini 悬浮条为纯白色卡片，犹如高光手电筒直射眼睛，完全没有适配暗色主题。
- **成因代码定位**: `tts_mini_player.dart` 内卡片直接使用了固定白底 `Colors.white`，未读取当前阅读器环境的 `colors.card` 与 `colors.textPrimary`。
- **优化方案**: 将背景与文字自适应绑定当前阅读主题配色，暗黑模式下采用深灰高质感毛玻璃微透效果。

### 2.4 [交互瑕疵] TTS 语速与定时设置按钮未封装 48dp 最小触控热区
- **真机实测现象**: 语速选项（0.8x、1.0x、1.2x、1.5x、2.0x）及定时分钟按钮，在 2K 高分屏上点击判定极易点偏漏触。
- **优化方案**: 为每一个选项标签封装 `HitTestBehavior.opaque` 与 `kMinInteractiveDimension (48dp)` 最小透明热区。

### 2.5 [功能缺失] 缺少系统发音人/音色选择与朗读句子正文跟随高亮
- **真机实测现象**: 用户无法选择男声/女声/地方口音，且朗读正文时页面不会随语音进度自动下翻或给当前句子着色高亮。
- **优化方案**: 接入系统 TTS 引擎可用 Voice 列表，增加正文当前句背景呼吸光晕高亮与自动翻页同步。

## 三、第 3 轮：目录树搜索、书签与划线批注全流程实测

### 3.1 [严重缺陷] 阅读器顶栏右侧「书签」胶囊被屏幕右边缘物理截断
- **真机实测证据**: 实测截图 `nr3_06_add_bookmark.png`
- **真机实测现象**: 阅读器顶栏在标准屏幕宽度下横向平铺了返回、书名、已入架、换源、笔记、书签 6 个操作项，最右侧的「书签」胶囊被手机物理右边缘生生裁切吞噬了一半。
- **成因代码定位**: `lib/features/reader/presentation/reader_screen.dart` 顶栏 `Row` 未使用换行、自适应或折叠更多菜单，在普通或紧凑宽度下发生水平溢出裁剪。
- **优化方案**: 将换源、笔记、书签合理归纳，或采用自适应溢出折叠（... 更多）机制，保障各屏宽下均严密居于可视区域内。

### 3.2 [视觉刺眼] 深色阅读模式下长按划线弹窗为大面积亮白卡片
- **真机实测现象**: 夜间纯黑背景下，长按文本呼出的「添加划线批注」Dialog 呈现大面积纯白背景，产生强烈的眩光暴击。
- **成因代码定位**: `reader_notes_sheet.dart` 中 Dialog 使用了默认主题 `Theme.of(context).cardColor`，未与阅读器当前私有色彩模式同步。
- **优化方案**: 传入当前阅读器 `SoftColors`，暗黑模式下使用深色沉浸卡片与防眩光次级高亮强调色。

### 3.3 [体验粗糙] 划线功能仅支持固定整句截取，不支持光标拖拽微调
- **真机实测现象**: 长按某处文本时，系统只能机械地将整句话一次性选入，无法自由拖拽选择句中的特定词语或段落。
- **优化方案**: 引入 Flutter `SelectableRegion` / `SelectionContainer` 原生长按拖选句柄能力。

### 3.4 [严重缺陷] 笔记抽屉内点击「导出笔记」，SnackBar 提示被抽屉完全遮盖
- **真机实测证据**: 实测截图 `nr3_12_export_with_data.png`
- **真机实测现象**: 在打开的书签/笔记抽屉中点击「导出笔记」，屏幕没有任何提示，用户误以为点击完全失效。
- **成因代码定位**: `lib/features/notes/presentation/reader_notes_sheet.dart` 中使用 `ScaffoldMessenger.of(context).showSnackBar`，其挂载在底层的 Scaffold 上，被当前处于最上层的 ModalBottomSheet 彻底遮挡。
- **优化方案**: 在抽屉内就地展示轻量级行内提示条，或在 `Navigator.pop` 后再触发 SnackBar，或使用自定义 Overlay Toast。

### 3.5 [体验瑕疵] 目录树搜索缺少关键词高亮与命中总数统计
- **真机实测证据**: 实测截图 `nr3_02_toc_search.png`
- **真机实测现象**: 在目录搜索框输入关键词过滤时，列表项中的文字没有把搜索词进行高亮渲染，也没有提示“共匹配到 X 处”。
- **优化方案**: 使用 `TextSpan` 对章节名中的匹配字符进行主题色高亮，并在列表顶端显示“找到 N 个相关章节”。

### 4.1 [严重功能缺失] 书架顶栏「本地导入」仅为纯文本弹窗，无真实文件选取器
- **真机实测证据**: 实测截图 `nr4_02_wifi_transfer_dialog.png`
- **真机实测现象**: 点击书架顶部「↑ 本地导入」按钮，弹出的对话框仅仅显示一段纯文本：“支持 TXT 与 EPUB，点 WiFi 传书更方便”，没有任何调用手机本地存储、下载目录选取文件的 FilePicker 或 SAF 流程！
- **成因代码定位**: `lib/features/shelf/presentation/shelf_page.dart` 的 `_showLocalImportDialog` 仅是一个静态展示型 `AlertDialog`。
- **优化方案**: 接入 `file_picker` 或系统存储访问框架（SAF），点击后直接唤起系统原生文件管理器，支持多选 `.txt` 和 `.epub` 文件并调用 `LocalBookService().importFile(...)` 一键入架。

### 4.2 [严重缺陷] WiFi 传书弹窗内点击「复制网址」无任何可见反馈
- **真机实测证据**: 实测截图 `nr4_05_copy_url.png`
- **真机实测现象**: 点击「复制网址」按钮后，没有任何 Toast 或提示弹出，用户完全不知道是否复制成功。
- **成因代码定位**: `lib/features/local_books/presentation/wifi_transfer_dialog.dart` 第 207 行的 `ScaffoldMessenger.of(context).showSnackBar` 同样被本 BottomSheet 完全遮挡在背后。
- **优化方案**: 改用当前弹窗内部状态反馈（如将按钮文字动态变为“✓ 已复制”，维持 1.5 秒），或使用自定义 `OverlayEntry` 顶部浮层。

### 4.3 [体验瑕疵] 书架网格模式信息层级过度砍伐
- **真机实测证据**: 实测截图 `nr4_08_grid_view.png`
- **真机实测现象**: 相比列表模式，网格模式下完全丢失了最新更新章节信息（如“第 1056 章 大干录”）以及是否有新章节的小红点。
- **优化方案**: 在网格卡片封面左上角或书名下方以精致小字展示最新章节及未读状态。

### 4.4 [视觉 / 语义混淆] 网格卡片将 12px 离线缓存图标与已读进度并排，被误认为“已读完”
- **真机实测证据**: 实测截图 `nr4_08_grid_view.png`
- **真机实测现象**: 在“0% 已读”右侧，紧贴着一个极度微小的绿色对勾图标（`Icons.download_done_rounded`），由于只有 12px 且没有任何文字，读者第一反应是“0% 怎么就打勾完成了”，造成严重的认知混乱。
- **成因代码定位**: `shelf_page.dart` 891 行，只孤零零放了一个 `Icon(Icons.download_done_rounded, size: 12.0, color: Colors.green)`。
- **优化方案**: 改为在卡片封面右上角或底部展示带文字的微型胶囊标识，如 `[✓ 3章]` 或专用的下载圆点标，与阅读进度严格解耦。

### 4.5 [严重缺陷] 长按书籍菜单点击「从书架移出」直接物理删除，无二次确认与撤销
- **真机实测证据**: 实测截图 `nr4_09_book_options.png`
- **真机实测现象**: 长按书籍呼出管理菜单，点击最后一行「从书架移出」，该书瞬间从书架消失，没有任何二次确认对话框，没有撤销（Undo）机制，误触率极高，造成不可逆数据损失；同时“置顶/取消置顶”图标错误使用了“垂直对齐”图标。
- **成因代码定位**: `shelf_page.dart` 第 225 行使用 `Icons.vertical_align_bottom`；第 237 行点击后直接执行 `removeBookFromShelf` 且未弹出确认框。
- **优化方案**:
  1. 修复置顶图标为 `Icons.push_pin_rounded` 与 `Icons.push_pin_outlined`；
  2. 点击移出时弹出确认对话框，并在移出后提供底栏 SnackBar `撤销` 动作。

## 五、第 5 轮：设置中心 WebDAV 云同步、端侧边界与全局 UX 体验实测

### 5.1 [严重缺陷] 设置页面「WiFi 局域网无线传书」条目硬编码伪造 SnackBar
- **真机实测现象**: 在设置页中点击「WiFi 局域网无线传书」，完全不呼出真正的传书弹窗，而是写死弹出一个伪造的 SnackBar：`'已启动本地服务：http://192.168.1.100:8080'`，这是早期残存的假代码！
- **成因代码定位**: `lib/features/settings/presentation/settings_page.dart` 第 200-204 行硬编码了该假交互。
- **优化方案**: 统一调用书架页同款的真正 `WifiTransferSheet.show(context)`，保持全应用传书服务同源同逻辑。

### 5.2 [严重缺陷] 离线正文缓存大小为写死静态常量，清理未执行实际物理删除
- **真机实测证据**: 实测截图 `nr5_06_clear_cache_dialog.png`
- **真机实测现象**: 设置页中的离线缓存大小恒定显示为 `'24.8 MB'`，点击确认清理后简单地将变量赋值为 `'0.0 KB'`，完全没有计算真实的磁盘/数据库缓存大小，也没有执行真实的物理清除。
- **成因代码定位**: `settings_page.dart` 第 19 行与第 56 行均为硬编码变量。
- **优化方案**: 接入真实存储服务，统计 Hive、SQLite 以及下载正文文件的实际字节数动态格式化显示；清理时真正物理删除缓存文件并重算容量。

### 5.3 [灾难性缺陷] WebDAV 在未配置账号密码时竟报告“同步成功”，状态自相矛盾
- **真机实测证据**: 实测截图 `nr5_04_test_connection_empty.png`、`nr5_05_sync_now_feedback.png`
- **真机实测现象**: 在账号、密码全空的情况下，先点“测试连接”提示红色错误“✕ 连接失败”，随后点“立即增量漫游”，界面竟然**同时显示**红色连接失败条和绿色“同步成功：书架 4 本 · 书签 1 个 · 笔记 1 条”，并伪造了上次同步时间！
- **成因代码定位**: `lib/features/sync/services/webdav_service.dart` 第 160 行：
  ```dart
  if (_isTestMode || !config.isConfigured) {
    return SyncResult(success: true, message: '已完成本地同步（未配置云端）', ...);
  }
  ```
  在未配置云端时直接返回 `success: true`，且 `WebDavConfigSheet` 在触发同步时没有重置清空上一轮的测试错误提示。
- **优化方案**:
  1. 在账号/密码为空时，禁用或提示“请先完善 WebDAV 配置”，严禁在未连接云端时谎报“同步成功”；
  2. 触发同步时重置所有历史状态条，杜绝红绿矛盾双显。

### 5.4 [严重缺陷] 物理音量键翻页与屏幕常亮开关未做持久化，阅读器内核完全无感知 (Ghost Toggle)
- **真机实测现象**: 用户在设置页中无论把“物理音量键翻页”开还是关，退出应用后配置立即丢失；且阅读器视口在收到音量键事件时，根本不读取此开关，一律无脑翻页！
- **成因代码定位**:
  - `settings_page.dart` 中开关的 `onChanged` 仅做了内部 `setState`，没有写入 `StorageService` / `SharedPreferences`；
  - `reader_viewport.dart` 中的 `_handleVolumeCall` 和 `_handleKeyEvent` 没有读取任何持久化开关。
- **优化方案**: 在 `StorageService` 增加 `volumeKeyPaging` 与 `keepScreenAwake` 的读写，在设置中更改时持久化并广播，阅读器视口根据开关决定是否拦截音量键及配置 Wakelock。

### 5.5 [功能缺失] 设置中心缺少全局主题外观（明亮 / 暗黑 / 跟随系统）切换选项
- **真机实测现象**: 应用内虽然底层支持多套主题色彩，但设置中心完全没有提供主题切换卡片，用户在主界面无法自由切换深色模式。
- **优化方案**: 在设置中心增加“外观与主题”卡片，支持纯白雅致、羊皮纸、水墨绿、极夜黑 4 款主题的全局一键预览切换与系统暗色跟随。

### 1. 【问题一：全屏与顶部状态栏对齐问题】全量分布盘点

## 八、26+8 项核心问题全景整改路线图

经过此轮专项地毯式排查，将上述新增的 8 处隐患与此前 26 项缺陷深度融合，形成最系统、彻底的统一重构方案：

1. **阅读器顶部状态栏与沉浸对齐改造**：
