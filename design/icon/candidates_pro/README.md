# 用专业图标库矢量合成的候选

## 为什么换这个做法

前面手工算坐标画形的两批（几何平面、几何立体）都不成立：螺线绕成蜗牛、
两段弧方向反了读成打钩、月牙路径写错根本没渲染出来。

真正让质量跳一档的是**用专业绘制的轮廓**——字体标那一批好看，
是因为用了字体设计师画的字形，不是我摆的点。不要字的话，
等价物就是专业图标库：严格网格、曲率连续、笔画粗细统一。

`compose.py` 只做一件事：把图标库的矢量按光学视框缩放、套上冰蓝配色系统。

## 来源与许可

| 来源 | 许可 | 用了哪些 |
|---|---|---|
| [Lucide](https://lucide.dev) | ISC | 线性：book-open-text / library / scroll-text / moon-star |
| [Phosphor Icons](https://phosphoricons.com) | MIT | 实心：books / scroll / book-open-text |

两个许可都允许商用，但**必须保留许可声明**。真正采用哪一个，
要把对应许可原文放进仓库（建议 `design/icon/LICENSES/`）。

## 必须知道的代价

**这些是通用图标，撞车风险实打实存在**——任何 App 都能用同一个
book-open。真要用，应当以它为基底再改造（改比例、换局部、加一个
自有的识别元素），改到不是「原样的 lucide book-open」为止。

单论辨识度，前一批的字体标（藏书印）更不容易撞。
